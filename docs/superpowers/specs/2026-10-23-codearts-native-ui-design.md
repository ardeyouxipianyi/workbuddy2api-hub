# CodeArts 原生 UI 对齐提案

状态：用户已确认原生布局和控件一起优化。

## 目标

让 CodeArts 页面沿用当前 WorkBuddy 的导航、主题、字体、间距、区块、按钮和表格。
保持七个已选模型、现有华为登录和请求路由；所有改动限定在 extensions/codearts。
不修改原 dashboard.html，不启动或停止 8788。

## 源码中发现的问题

- 当前所有内容堆在一张最大宽度 1100px 的卡片中；原页面采用全宽区块与工具栏。
- 输入框使用 --border、--bg2、--text；原主题使用 --line、--panel2、--fg，存在主题样式未生效风险。
- 操作统一使用 btn，没有原生主按钮、sec、mini 和 danger 的层级。
- 账号与模型是文本行，缺少与原账号表一致的列对齐、状态徽标及窄屏处理。
- 连接参数优先占据首屏，账号操作和模型被推到下方。

## 两种方案

1. 推荐：原生布局和控件一起对齐。日常账号、模型操作优先；服务配置折叠，沿用原生主题。
2. 小范围：只统一配色、按钮和输入框，保留现有单卡片纵向布局。改动少，但首屏密度与操作层级问题仍在。

## 推荐方案的页面结构

顶部：CodeArts 标题、服务连接徽标、刷新状态按钮。
下方：原生 cards 摘要（账号数、可用账号数、请求数、Tokens）。请求与 Token 注明最近 5000 条网关记录。

账号区：原生 section + toolbar/tb-group + table-wrap/data-cards。
- 工具栏保留登录华为账号、检查登录结果、全员签到、重载账号。
- 表格列：账号、启停状态、Token 剩余时间、操作（续期、签到、启停）。
- 字段只取现有接口；缺失显示“未提供”，不推算登录活跃时间或伪造积分。
- 空账号提示直接引导登录。登录窗口仍同步打开并保留授权链接兜底。

模型区：原生 section + table-wrap/data-cards。
- 保留七个已选模型。
- 列：模型名称、客户端模型 ID、后端目录状态、操作（复制 ID、选中测试）。
- 目录状态只代表目录是否列出，不把目录存在显示成真实调用通过。
- 参数只在接口实际提供时展示，不硬编码能力或价格。

请求测试区：原生 disclosure 可折叠区块。
- 保留模型选择、消息输入、显式发送按钮。
- 当前请求结果显示正文、耗时和上游提供的用量/错误；没有结果时显示空态。
- 刷新页面状态不重置测试选择、输入和已有结果，不自动发送上游请求。

连接设置区：原生 disclosure 可折叠区块。
- 保留启用开关、后端地址、服务密钥、密钥环境变量、超时及保存。
- 常用字段与高级字段分组。配置完整时默认收起；未配置时展示操作引导。
- 显示当前网关 /v1 入口及 codeart/ 用法。
- 不回显保存的服务密钥；不覆盖正在编辑但未保存的内容。

## 视觉与交互约束

复用 --fg、--dim、--panel、--panel2、--line、--accent、--bad 等原生变量，以及
section、cards/card、toolbar/tb-group、sec/mini/danger、badge、hint、table-wrap/data-cards。
新增样式只作用于 #pageCodearts；不复制或全局覆盖原生样式。
保持现有简体/繁体/英文入口，支持主题切换、键盘焦点与窄屏表格/布局。
加载、未启用、后端离线、无账号、空模型、操作成功和操作失败分别显示明确状态。
刷新局部数据失败时保留已经加载的其它区块。

## 验收

- 源码与自动检查：扩展 UI、登录弹窗、模型选择、配置保密与现有网关回归。
- 浏览器：宽屏/窄屏、深浅主题、简繁英、导航切换、账号/模型布局、加载/失败状态、无 JS 错误。
- 提交遵循 CONTRIBUTING 门禁，使用隔离端口；真实上游请求保持最少次数。
- 当前浏览器工具拒绝读取 8799 页面，尚未完成实时视觉验收；不会绕过该限制。
