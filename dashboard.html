定價重新整理

閘道每隔這段時間去 OpenRouter 取一次價：每個模型每份不同的價格存成一條定價策略（內容相同就重用同一條，不重複寫），並宣告「現在生效的是哪一條」。每條請求按它發生時生效的那一條計價，所以之後調價不會改寫之前的數字；請求只記它引用的是哪條策略，不內嵌整份價格。取價時還沒有價的模型，用之後第一次取到的價補算並標 *。沒人引用、又已經不作數的策略會被清掉（每個模型至少留一條，剛取到的那批不動）。取價間隔以分鐘計，預設 5 分鐘；填 0 表示不自動重新整理（仍可用「立即取價」手動取一次）。
取價輸入 = 內建目錄 ∪ 閘道即時目錄裡新增的模型，上游新上架的名字無需改程式碼就會進入下一輪取價；兩次取價之間就被呼叫的新模型，第一筆請求即按記憶體裡的目錄按需補價。名字帶通道字尾（如 -lkeap）的模型預設按變體字尾繼承向基準模型取價（要求唯一命中，命不中照舊顯示未定價）；關掉開關即恢復「只有覆蓋表與同名匹配才定價」。
重新整理間隔（分鐘）

429 自動切換出站身分

某帳號在某模型上被上游限流（429）時，自動在 WB / VSC / CLI 之間換身分重試，每輪最多 4 次。三條身分走不同的配額通道，開啟後 429 會少一些。預設關閉。
注意：切換後的身分會被儲存，重啟後繼續沿用，不會自動回到 WB。

國際版每日活躍打卡

國際版帳號每日打卡時，除桌面端身分的輕量對話外，再走一次網頁通道的會話（在 console/as 下建一個帶 prompt 的會話）。實測只有網頁端對話會被計入官方「每日活躍」，桌面身分的對話不計入。預設開啟。
注意：網頁通道會真的起一次任務，消耗該帳號少量積分，換來的是每日 30/50 積分活躍獎勵。

本機網路工具 (web_search / web_fetch)

部分客戶端（如 Codex App）會宣告 web_search / web_fetch 這類服務端工具，而上游沒有對應的執行器：宣告送上去，模型看到工具卻沒有執行器，客戶端最後只拿到一句 unsupported call。開啟後由本閘道代跑——把宣告換成自己的同名函式，在本機執行（搜尋走 DuckDuckGo，抓頁面抓這個 URL）再把結果餵回模型。預設關閉，關閉時宣告原樣透傳，客戶端自己宣告的搜尋工具照常拿到呼叫。
注意：開啟後閘道會主動出網抓取模型給出的 URL（只擋字面私網地址），且每輪代跑都會多跑一次上游、多消耗該帳號的額度；國內網路下 DuckDuckGo 可能連不上，那時模型拿到的是錯誤文字。
